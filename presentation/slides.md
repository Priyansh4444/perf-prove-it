# The code

before and after, per call over 200 candidates

````md magic-move {lines: false}
```ts
// before: 7 closures + 204 temporaries per call
const raw = candidates.map((c) => ({
  rel: signalRel(c),
  eng: signalEng(c),
  auth: signalAuth(c),
}));

const z = {
  rel: maxSignal(raw, (r) => r.rel),
  eng: maxSignal(raw, (r) => r.eng),
  auth: maxSignal(raw, (r) => r.auth),
};
```
```ts
// after: 1 closure + 3 output arrays, same output
const rels = new Array(candidates.length);
let zRel = 1e-9, zEng = 1e-9, zAuth = 1e-9;

for (let i = 0; i < candidates.length; i++) {
  const c = candidates[i]!;
  const rel = signalRel(c);
  const eng = signalEng(c);
  const auth = signalAuth(c);
  rels[i] = rel; engs[i] = eng; auths[i] = auth;
  if (rel > zRel) zRel = rel;
  if (eng > zEng) zEng = eng;
  if (auth > zAuth) zAuth = auth;
}
```
````

# Opt

`--trace-opt` on the same harness. The cold code is interpreted, the hot code is compiled.

```text {1|2|3|4|5}
[marking <JSFunction maxSignal> for optimization to MAGLEV, reason: hot and stable]
[completed compiling maxSignal (target MAGLEV) - took 0.000, 1.220, 0.005 ms]
[marking <JSFunction rerank> for optimization to TURBOFAN_JS, reason: hot and stable]
[completed optimizing rerank (target TURBOFAN_JS)]
# no deopt lines
```

<v-click>

Maglev is the mid tier. TurboFan is the top tier. If a function deoptimizes, you were measuring the interpreter and did not know it.

</v-click>

# Deopt

the first A/B run said the new arm was 16x faster

```text {1|3-5|6-7|8-9}
# first A/B run: the new arm looked 16x faster
[bailout (kind: deopt-eager, reason: wrong map): begin.
 deoptimizing <JSFunction rerank>, <Code TURBOFAN_JS>,
 opt id 68, bytecode offset 3, deopt exit 52]
[bailout (kind: deopt-eager, reason: Insufficient type feedback
 for generic named access): deoptimizing <JSFunction escalate>]
# two bundles in one process deoptimized each other
# thrown out. arms rerun in separate processes.
```

<v-click>

`wrong map`: the object's hidden class changed under compiled code. Two bundles in one process deoptimized each other. The 16x was thrown out, and the report says so.

</v-click>
