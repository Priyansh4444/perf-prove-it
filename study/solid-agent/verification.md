# Independent verification: context-free agent on solidjs/solid

Date: 2026-09-10. Environment: Node v26.8.2 (V8 14.6), 16 cores, Linux x64. Load average 2.5 to 3.2 across the sessions below.

## What was tested

A subagent with no prior context was given only:

- the skill at `skills/perf-prove-it-ts/SKILL.md` (with its references and scripts)
- a clone of `solidjs/solid` at `/tmp/opencode/solid-sandbox` (commit `5dc898a` plus a benchmark-harness fix, see below)

Success criterion: a win verifiable with the repository's own benchmark (`packages/solid/bench/bench.cjs`) and test suite.

## Preconditions set by the orchestrator (not given to the agent)

- The 2022 benchmark crashed on V8 14.6 because `%OptimizeFunctionOnNextCall` now requires `%PrepareFunctionForOptimization`. The sandbox baseline commit adds the missing prepare call. Without it the bench aborts with SIGTRAP. This is a harness fix only, and the harness was frozen for the agent.
- Baseline runs of the frozen benchmark before the agent ran: totals 441, 498, 450 (median 450) on a 5-run series.
- The agent was told the benchmark harness itself must not change, and it did not: `git diff HEAD` shows only `packages/solid/src/reactive/signal.ts` (28 insertions, 33 deletions).

## Agent result as claimed

- Unit: packed subscription edges in `signal.ts`, one array per edge side instead of parallel `observers`/`observerSlots` and `sources`/`sourceSlots` arrays.
- Claim: total median 391 to 339.5 ms (-14.6%), 18 of 20 paired blocks faster, sign test p = 4.0e-4; A/A control median +3.4% with p = 0.115.
- Identity: repo suite green, 7-seed differential and structural edge harness with 0 mismatches.

## Independent reproduction

Bundles were rebuilt in the verifier's own session and hashed against the agent's saved arms:

```text
before (pristine HEAD): 24bbf7a129e16b70811f1eb7e5970439248533e9a2eaee5b3492ccaa98704add
after  (patched source): 41be471669ebd2048def98226877418c3540979e9445d4d1dc42d639055de476
agent arms identical: yes
```

Tests on the patched tree: `pnpm --filter solid-js exec vitest run` = 27 files, 487 passed, then the server suite 4 passed.

Benchmark A/B (fresh process per run, bundle swapped, one bench execution per arm):

| session | pairs | patches faster | paired median | totals (median before to after) |
| --- | ---: | ---: | ---: | ---: |
| first 5-pair run | 5 | 4 of 5 | -20 ms | 366 to 370 (parity, underpowered) |
| 12-pair alternating | 12 | 11 of 12 | -61 ms | 394 to 313 (-20.6%) |
| 6-pair counterbalanced (patched first on 3) | 6 | 6 of 6 | -61 ms | 383 to 329 (-14.1%) |
| combined | 18 | 17 of 18 | -61 ms | 392.5 to 326 (-17.0%) |

Sign test, one-sided: 17 of 18 in one direction, p = 7.2e-5. In the counterbalanced subset the patched bundle also won when it ran first, so the effect is not an arm-order artifact.

## Verdict

Confirmed. The agent's headline direction and rough magnitude reproduce (agent -14.6%, verifier -17.0% combined). The first verifier run of 5 pairs landed on parity, which is the lesson: this benchmark's single-run spread is roughly 15%, so fewer than about 10 pairs cannot resolve a 15% effect. The agent ran 20 pairs with an A/A control, which is the right protocol; the verifier needed the same.

Not independently verified here: the agent's memory claims (peak RSS, scavenge counts) and the generated bytecode sizes. The report labels those artifacts.
